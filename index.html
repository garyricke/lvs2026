How this differs

Products 01–02 start from a single 2D image and use generative AI (Veo) to imagine the rotation — fast and photoreal, but the AI guesses hidden faces and can subtly morph the geometry. This new method renders directly from the supplied 3D CAD: dimensionally accurate, repeatable across the whole product line, and free of AI artefacts. The trade-off is a cleaner, more technical finish rather than a fully photographic one. The same STEP files scale to Small, Medium and Large.

Build record · May 2026

A full record of how these captures were produced — the diagnostics, colour corrections, regenerations, and tooling behind both product spins, in the order they happened.

R012026-05-28

Colour metadata fix

  • The original 360° video looked orange in players, yet measured as deep red in analysis.
  • Diagnosed the cause: the file carried no colour metadata (no colr atom). The untagged 720p H.264 was encoded with the BT.601 matrix, but players assumed BT.709 — shifting the reds toward orange.
  • Stamped explicit BT.601 (smpte170m) tags via a lossless stream-copy — no re-encode, no quality loss.
ffmpegh264_metadata bsfOpenCVPython
R022026-05-28

Deep-red colour grade

  • Compared the render to the real cabinet: its green channel was too high (hue 5–8 vs the real hue 2), reading orange.
  • Built an HSV grade — hue shift, saturation and value adjustment, plus highlight green-reduction — and colour-corrected the studio still and video toward the true deep red.
OpenCV + NumPyHSV grading
R032026-05-28

Regenerate spin — panel-pop artifact

  • A panel "popped in" on the side mid-rotation — a generative artifact of the original video, not fixable by colour grading.
  • Produced a corrected deep-red still, uploaded it to the fal CDN, and regenerated a clean, rigid 360° turntable from it.
Veo 3.1 (fal.ai)fal REST API / CDN.env key
R042026-05-28

Deepen red & correct depth

  • The new spin still read too orange under bright studio light (a perceptual effect), and the shallow ~1.5 ft cabinet looked like a deep box — Veo had over-extruded its depth.
  • Deepened the red to a darker, richer crimson, and regenerated with a prompt enforcing a thin, shallow, wide-flat profile. Re-tagged BT.709.

Technical clarification
  • Best input — a native 3D CAD model (STEP / 3D solid): exact geometry and dimensions, so the turntable is dimensionally correct with no guesswork. The file used here was a 2D isometric drawing (a single view), which is why depth had to be estimated and corrected.
  • Multi-view photos (front / side / back) are the strong photo-based alternative — but they feed a 3D-reconstruction or multi-reference pipeline, not the single-image video model used for these first spins, which infers the unseen sides.
  • Expect highly accurate rather than literally perfect: geometry can be matched closely; fine surface and label detail may still vary.
  • Once the input formula (3D model or calibrated multi-view set) is fixed, repeat generations are fast and consistent.
